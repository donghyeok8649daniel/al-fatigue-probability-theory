# Al UI 외삽 표시 수정 — 2026-09-20

## 범위와 확인된 원인

사용자는 Al 선택 상태에서 외삽 숫자·곡선·메시 위험도가 모두 보이지 않는다고
보고했다. 사용자의 열린 창은 native pipe 연결 오류로 직접 읽지 못했다.
별도 실제 Tk UI에서 두 표시 결함을 재현하고 수정했다.

1. 기본 3D 면하중 경로가 국소 PDE의 기록 callback을 UI에 전달하지 않아,
   전체 계산이 끝날 때까지 숫자와 곡선이 비었다. 최종 주 창 결과와 같은
   첫 대표 PDE의 실제 기록을 전달한다. 다른 대표의 시간축을 이어 붙이지 않는다.
2. 프로젝트를 열 때 원래 국소 확률과 면적 입력이 있어도 저장된 외삽 표시값이
   없거나 오래된 경우 갱신하지 않았다. 복원한 입력으로 외삽을 다시 계산한다.

면적 입력 안내의 잘못된 Pre 위치도 Solve로 수정했다. Al/Si 선택, 에너지,
SG generator, 실제 흡수량, 수치 하한, 인증 gate와 공간 해석은 변경하지 않았다.
Si 생산 실행과 물리 Hz는 계속 비활성이다.

## 표시 조건

- Solve의 면적 외삽: `A_c > 0`, `A_stressed >= 0`이 필요하다. 3D 실행에서는
  첫 대표의 국소 확률에 적용하는 독립·등가 영역 가정이며 미인증 수학적 외삽이다.
- 공간 컬러맵: 모든 대표 PDE를 완료한 실제 공간 결과를 사용한다.
  체적 위험도에는 별도의 `V_c > 0`이 필요하다. 임의 기본값은 추가하지 않았다.
  국소 확률과 응력 지도에는 `V_c`가 필요하지 않다.
- 외삽과 표시 갱신은 PDE를 다시 실행하지 않는다. 저장된 원시 이력과 공간장은
  유지한다. 미인증 외삽을 수렴 인증 확률로 승격하지 않는다.

## 실제 검증

검사 명령은 저장소 루트에서 `python -m pytest ... -q --tb=short`다.
수치 라이브러리 스레드는 `OPENBLAS_NUM_THREADS=1`, `OMP_NUM_THREADS=1`로 설정했다.

| 검사 | 결과 |
|---|---|
| 수정 전 callback/실제 UI 회귀 | 예상 실패 2건: callback 인자 없음 / 실행 중 기록 없음 |
| callback 수정 후 같은 검사 | 2 PASS / 37.25 s |
| 복원 수정 전 실제 UI 회귀 | 예상 실패 1건: 외삽 배열 `KeyError` |
| 복원 수정 후 같은 검사 | 1 PASS / 40.20 s |
| `python -m pytest app` | 188 PASS + 3 subtests, 제한시간 초과 1건 |
| 제한시간 초과한 동일 검사 재검증 | PASS, 최종 고유 189개 모두 통과 |
| 원래 실행 폴더의 집중 검사 | 16 PASS / 91.73 s |
| `python -m app.desktop_ui --smoke` | exit 0, canonical a0/kappa 일치 |

전체 검사는 실행 도중 절전·최대절전이 끼어 경과 시간이 43,593.60 s였다.
Windows System 로그에서 02:51:49 덮개 절전, 12:22 최대절전,
14:53:44 복귀를 확인했다. 실패는 실제 UI 검사의 150초 deadline 초과였다.
한 번의 깨끗한 전체 PASS로 기록하지 않는다. 전체 검사의 188개 통과와
실패했던 같은 node의 재검증을 대조해 고유 189개 최종 통과를 확인했다.

실제 UI 검사는 평형 끝면 하중에서 실행 중 기록, 외삽 수치와 곡선의 일치,
미인증 상태 유지, 응력/국소 확률/세 체적 위험도 컬러맵, `V_c` 변경,
절단/언어 전환, 누락·오래된 외삽 표시값을 가진 저장 파일의 복원을 검사한다.
원래 실행 폴더에서는 이 UI 검사, 실제 3D→PDE 저장 검사,
`app/test_specimen_ui_update.py`를 다시 실행했다.

## 배치와 한계

수정·검증은 `silicon-wafer-research`의 기반 `3987f248`에서 수행했다.
검증한 공통 코드·테스트·설명 8파일의 변경만 원래 UI 작업 폴더에도 적용했고,
기존 내용의 SHA-256 확인 후 적용 및 두 위치의 줄바꿈 정규화 일치를 검사했다.
기존 Al 연구 변경과 다른 사용자 파일은 보존했다.

이미 열려 있던 UI 프로세스는 강제 종료하거나 메모리를 수정하지 않았다.
작업을 저장하고 UI를 다시 열어야 새 코드가 적용된다. 사용자의 현재 미표시
조건 자체를 직접 확인한 것은 아니며, 위 재현 사례와 표시 조건의 검증이다.
새 재료/kinetic calibration 또는 시편 확률의 물리 인증을 주장하지 않는다.
