# CAD와 피로시험 연구 자료 연결

피로시험기 브랜치는 실제 장비의 기구·전장·계측·펌웨어 준비를 관리한다.
확률 연구 코드와 연구 UI는 각 연구 브랜치에서 유지한다. CAD는 이 자료를
설계 참고자료로 읽으며, 참고 연결만으로 솔버나 실제 액추에이터를 실행하지 않는다.

## 참고자료 구성

`../research/reference_manifest.json`은 게시된 자료의 브랜치, 커밋, 경로,
SHA-256, 파일 크기와 원문 URL을 기록한다. 링크는 당시 읽은 커밋에 고정되어
있다. 확률·Si 브랜치의 참고 문서 10개는
`../research/published/<원본 브랜치>/<원본 경로>`에 원문 바이트 그대로 모았다.
`local_repository_path`로 이 사본과 기존 시험기 파일을 찾을 수 있다.
원문 안의 상대 링크가 누락된 연구 파일을 가리키면 고정된 원문 URL을 사용한다.
다른 연구 브랜치의 진행 중 변경이나 개인 바탕화면 CAD를 합친 목록이 아니다.

기존 `fatigue_tester/firmware`, `hardware`, `pc`, `docs`를 보존하고,
연구 내용을 다음 네 범주로 구분한다.

- 장비 요구조건: 축하중, 구동부, 로드셀, 변위·변형률, DCPD, 온도, 안전, 통신.
- 교환 인터페이스: 프로젝트 파일, 표면 하중의 단위·메시 식별, 측정 CSV.
- Al 참고: 원통 시편의 공개 시험 조건과 결과의 의미.
- Si 참고: 별도 결정 배향·균열 형상·하중 방법과 미검증 연구 단계.

현재 목록은 `fatigue-tester@399ffb1`, `probability-pde-solver-v1@c8ccff7`,
`silicon-wafer-research@8f9f754`의 게시 자료를 확인한 기록이다. 최신 연구를
설계 근거로 추가할 때 새 커밋을 확인하고 목록을 갱신해야 한다. 원본 연구
브랜치를 통째로 시험기 브랜치에 병합하지 않는다.

## 시편과 장비 정격

Al 원통 시편과 Si 웨이퍼의 그립·고정구·하중 방법을 공유한다고 가정하지 않는다.
Si 연구의 나노 시편 강성은 거시 Al 시편 또는 제작 중인 프레임의 강성이 아니다.
게시된 v15 CAD 읽기 기록의 Ø8 mm 시편도 그 당시 설계의 기록이다.
현재 설계의 치수는 현재 CAD 파일에서 다시 확인한다.

최대 하중, 반복 주파수, 왕복거리, 장비 강성, 최종 구동기와 센서는 미확정이다.
BOM의 2 kN·750 W·20 Hz 및 판매가는 과거 선정 후보와 예산 자료이며 현재
장비 정격이나 최신 가격이 아니다. 시편 단면적과 응력 조건에서 요구 힘을 구하고,
구동기의 힘·속도·가속도·스트로크·열/반복 운전 조건을 함께 확인한다.

공개 Al 피로 자료의 `full_range`는 최대값−최소값이다. 이를 진폭으로
그대로 입력하지 않는다. 일정 속도 분기의 삼각 반복 시험을 사인파로 임의
변경하지 않는다. 문헌 조건은 참고 자료이며 이번 장비의 확정 시험 조건이 아니다.

## MCU와 PC의 경계

기존 C 코어는 반복 하중 생성, PI 힘 제어, 고장·이동 한계, 안전 출력과
telemetry 인터페이스의 하드웨어 독립 골격이다. 보드에 바로 올릴 완성된
펌웨어가 아니다. 보드별 HAL, 센서 교정, 제어 주기, 구동기 명령, 실제 제어
이득, 독립 E-stop/인터록과 배선 검증이 남아 있다.

STM32 ESC의 모터 속도 제어와 시험기의 로드셀 힘 제어는 서로 다른 제어
계층이다. CAD의 평균 모터 모델이나 엔코더 계산을 실제 FOC 펌웨어 실행,
실제 힘 제어 검증 또는 제작 정격 인증으로 해석하지 않는다.

연구 확률 solver는 PC의 별도 연구 계층이다. 실측 seconds/Hz를 기록해도
생산 PDE의 무차원 시간에 대한 보정이 자동으로 생기지 않는다. 미보정 시간,
재료·확률 한계를 설계가 해결한 것으로 표시하지 않는다.

## MCU CSV에서 CAD 측정 양식으로

완료된 로그를 원본 그대로 보존한 상태로 다음 도구를 사용한다.

```text
python fatigue_tester/pc/measurement_csv_adapter.py raw_telemetry.csv measurements.csv --time-basis physical_seconds
```

`physical_seconds`는 MCU 로그의 `time_s`가 실제 초임을 명시하는 선언이다.
무차원 모델/PDE 시간은 거부한다. 센서 교정과 실제 시간 정확도를 이 도구가
검증하거나 보정하는 것은 아니다.
실제 로그를 변환하기 전에 `displacement_m`가 크로스헤드/구동계 이동 채널임을
확인한다. 시편 게이지 변위를 이 열로 기록한 로그는 채널 정의부터 구분해야 한다.

| MCU 열 | CAD 열 | 처리 |
|---|---|---|
| `time_s` | `time_s` | 실제 초를 그대로 유지 |
| `cycle` | `cycle_index` | 정수 사이클 번호 유지 |
| `force_n` | `force_N` | 측정된 부호 있는 힘 유지 |
| `displacement_m` | `crosshead_displacement_mm` | m→mm, 1000배 |
| `temperature_c` | `temperature_C` | 측정 온도 유지 |
| `strain` | `gauge_strain` | 독립 시편 게이지 채널임을 별도 선언한 경우만 |

원본 `strain`이 독립 extensometer/게이지의 시편 변형률임을 확인했다면
`--strain-channel-is-gauge`를 추가한다. 선언하지 않으면 `gauge_strain`은
비우고 확인 필요 표시를 남긴다. 크로스헤드 이동에는 프레임·그립·구동계의
변형과 미끄럼이 포함되므로 게이지 길이로 나눠 시편 변형률을 만들지 않는다.

결과는 세 파일이다.

- `measurements.csv`: CAD 측정 양식. 빈 값은 빈 값으로 보존한다.
- `measurements.source.csv`: 원본 로그의 정확한 바이트 사본.
- `measurements.metadata.json`: 원본/변환 파일 해시, 매핑, 단위, 모든 원본
  채널·레코드와 품질 표시. `stress_ref_pa`, `force_ref_n`, `dcpd_v`,
  `actuator_command`, `fault_flags`, 추가 센서 열도 보존한다.

이름이 같은 결과 파일은 덮어쓰지 않는다. 잘못된 숫자·중복 헤더·줄어드는
시간/사이클은 결과를 게시하기 전에 거부한다. 누락 값은 0으로 채우지 않는다.
같은 시간의 레코드는 삭제하지 않고 `duplicate_time_s`로 표시한다. 고장 플래그는
`quality_flag`에 표시하며, 원본 고장 마스크도 사본과 JSON에 그대로 남긴다.
빈 양식에는 데이터가 없다고 표시한다. 빈 양식이나 생성한 예제를 실측 결과로
취급하지 않는다.

이 도구는 표준 Python 라이브러리만 사용한다. 솔버, 장비 통신, 실제 구동,
펌웨어 업로드, 물리 시간 환산이나 응력/변형률 교정을 실행하지 않는다.
결과 파일은 같은 출력 폴더의 임시 파일을 하드 링크로 게시하므로 NTFS처럼
하드 링크를 지원하는 파일시스템을 사용한다. FAT/exFAT USB 저장소에서는
변환이 실패할 수 있으므로 NTFS에 변환한 세 파일을 함께 복사한다.
